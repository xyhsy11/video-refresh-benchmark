# Recommended next experiment: 23A, fresh-population and training-separation gate

The next experiment should be **input-only population feasibility for a genuinely fresh RGB evaluation with independent head-training, task-probe/controller-training, selection and evaluation source families**. It is not another controller architecture search. This commit does not execute it or select a dataset using exposed outcomes.

Before naming a dataset eligible, retain authorized original RGB bytes/labels, official metadata/version/terms/URLs and hashes; require user review for new access agreements. Obtain real source/subject/take/camera-family identifiers, audit exact/perceptual duplicates and unknown reuploads/pretraining overlap, keep related views/takes together, and preserve official evaluation boundaries. No outcome-based family splitting, substitution or dropping hard classes.

Predeclare all target classes and per-role independent-family minima from input metadata. Verify genuine PTS/snippet eligibility and full-class availability, then solve global family-level role allocation. If groups or resources are insufficient, report a population-design/resource blocker rather than execute an underpowered favorable subset. Freeze training-role sizes and the primary estimand before recognition outcomes. The HMDB51 conservative NO_GO remains a historical population result; exposed UCF official-test evidence is not a fresh dataset.

The recognition head must fit head_train only. Task-utility fitting sources must be separate so near-zero in-sample head losses do not define controller targets; selection/calibration must use separate source groups. Inspect target-scale/coverage on training/selection only. The present head-overlap contrast (periodic CE0.005321 on probe training versus0.516109 on selection) makes this separation a substantive design concern, not an administrative change.

Project disk/network and full-class compute using authorized input metadata and a later, separately approved training-only smoke. No evaluation encoder calls belong to this gate. Prespecify group-based uncertainty/precision planning and prohibit test extension after outcomes. Actual candidate timing and exact four-forward execution must be measured in any later policy experiment, with native projection, current-frame acquisition and all decision costs included.

Only after population and cost gates pass should a separately reviewed Experiment23B consider ONE fixed, task-targeted, explicitly cost-aware causal policy with independently frozen head/roles/thresholds and a fresh pre-exposure seal. Its task target must distinguish immediate from hindsight utility; expected improvement cannot be inferred from an oracle. A proposed cheaper/fused thumbnail path requires separate real fresh-decode timing verification and quality/logit agreement. Do not assume it is fast or useful.

Current manuscript work can proceed with the honest exploratory evidence: fidelity/task objective mismatch, proxy versus true-label headroom, history versus cheap observability, state-distribution dependence, and actual overhead. Neither this CPU study nor the recommended gate establishes TMLR readiness or independent confirmation. Stop here; no new data agreement, download, GPU work or controller training is authorized by this recommendation itself.
